# AGENTS.md

SkillUp Forever is a WoW: Forever addon (Interface 16001) that adds skill-up chances, costs and a levelling route to
the Professions window. It needs ForeverCore (declared in `## OptionalDeps`; the release pinned in `tools/forever-core.txt` ships in the zip),
which owns the tracker column, report window, leaderboards, error journal, settings chrome and context menu. Players
install the zip the BigWigs packager builds on a `v*` tag.

## Commands

```sh
python3 tools/doctor.py             # first on a new machine: every tool pin, with a fix for each problem
python3 tools/gate.py               # the fast local gate: format, lint, typecheck, specs, generated data, changelog
python3 tools/gate.py --changed     # only the steps the diff against origin/main reaches
```

`gate.py` loads ForeverCore from `$FOREVER_CORE`, else `../forever-core`: set it in a worktree. CI adds the simulator,
`tests/bench.lua` (timed by Speedpatrol against the base), the package build, actionlint, zizmor and gitleaks.
A change's player-facing notes go in `changes/<issue>.md`; only the release commit edits `CHANGELOG.md`
(`python3 tools/changelog.py release X.Y.Z`). Release: `.agents/skills/release/SKILL.md`.

## Layout

- `Data/*.lua` is generated by `tools/gen_*.py` (`tools/README.md`); never hand-edit. `refresh-data.yml` runs
  `tools/bump_pins.py` daily (generator pins to their newest upstream), regenerates and opens a `data/refresh` PR;
  `retry-refresh.yml` re-runs a failure once, then files "Data refresh failed". The classic-db pin is a waiver
  below and moves by hand.
- `Integrations/Questie.lua` and `Integrations/AtlasLoot.lua` are the only readers of the player's QuestieDB and
  AtlasLoot, through their public tables; nothing from either is copied into the repo, zip or a test (fixtures are the
  synthetic `Client.QuestieDB` and `Client.AtlasLoot` in `tests/client.lua`). `Integrations/Catalogue.lua` joins them
  into `ns.Catalogue`, built on first ask, kept for the session and read through one queue (at most 32 records or
  1 ms a frame); everything else treats nil as "not read yet or not installed". A vendor seen selling a reagent or
  scroll is saved in `ns.db.sellers`.
- `Core/Core.lua` registers the shared services once (`ns.core`); the tracker section lives in `UI/Shopping.lua`.
  Everything shared is ForeverCore's: never copy one of its files here.
- `Core/Model.lua` and `Integrations/Prices.lua` are the headless-testable maths (sub-craft cost: the cheaper of
  buying and crafting a reagent, three levels deep, memoised, cycle-safe). `Core/Live.lua` is the client's own recipe
  read and live grey threshold; bundled thresholds stay the fallback for the fourth number only.
- `Core/Plan.lua` is the levelling plan in base skill with trainer requirements resolved; the route page, tracker,
  public API and trainer window draw what it returns and never read the modifier or trainer tables.
- `Core/Changes.lua` decides what goes stale: a writer calls `ns.Changed(kind)`, game events arrive on its one frame.
  No file clears or redraws another's cache or view: own one with `ns.WhenStale`, per-event work with `ns.WhenEvent`.
- `Locales/enUS.lua` makes `ns.L` keyed by the English phrase, text is a whole `L["..."]` phrase;
  `python3 tools/phrases.py > Locales/phrases.txt` after a change (`tests/locale_spec.lua` checks both).
- `tools/forever_tools/` and `tools/forever_sim/` are vendored from forever-core: never edit them here.

## Rules

- Lua 5.1 in the game's sandbox: no `require`; a new file goes in `SkillUpForever.toc` or never runs.
- `tests/client.lua` is the shared stub client: it loads ForeverCore first (`tests/forever_core.lua` finds the
  checkout), then the TOC in order; a spec sets what the client holds, not an `ns` function. Frames, menus, tooltips
  and the tracker are checked in the headless client (`wow-forever-addon` `in-game.md`); the PR lists what was checked.
- A recipe colour always comes from the game; bundled thresholds only fill in what it does not show. Missing data
  renders `?`, never a guess. A gathering node has no colour in the game: its tooltip colours your live skill against
  the node's waivered requirement with Classic's gathering bands (orange to 25 past it, yellow 50, green 100), matched
  by enUS name, so other locales show nothing. A corpse shows `?` until `CORPSE_RULE_CONFIRMED` in `Core/Model.lua`.
- Keep tracker sections in the shared column: build one with `ForeverCore.TrackerSection.Create`, give its lines
  `TrackerLine.SetInteractive` and its menu `AddHeaderMenuEntries`; never create the frame, attach it or read an
  anchor by hand, and never register with Blizzard's tracker manager. Render only after `PLAYER_ENTERING_WORLD` and
  `VARIABLES_LOADED`, deferred one frame; this supersedes WFA-5's native registration guidance.
- Never touch Blizzard's Lua state (WFA-38); restyle a Blizzard element by drawing on top of it.
- Never stretch art: draw at native aspect through `UI/Art.lua` (`Art.Fit`, `Art.Markup`); `tools/lint_art.py` refuses
  a raw setter elsewhere unless its line says `-- art-ok: reason`.
- Host globals go in `.luacheckrc`, missing Forever or integration APIs get real types in `types/`, never
  `diagnostics.globals`. A scalar `select(...)` in last position is parenthesized or carries `-- multi-value: reason`.
- Before cleanup, dead-code or refactoring work, read the live roots and settled shapes in `.sloppatrol/instructions.md`.

## Waivers

WFA-28 exceptions, each from CMaNGOS classic-db unless noted, because neither QuestieDB nor AtlasLoot holds it; what
the client shows at a window wins over the bundled value:

- Trainer fees, rank fees and requirements (`Data/Trainer.lua`, `npc_trainer`); a fee read at the trainer replaces it.
- Which NPC trains which profession and cap (`ns.ProfessionTrainers`) and which recipes (`ns.TrainerSets`,
  `ns.RecipeTrainerSets`); the trainer's name, side and place are QuestieDB's.
- Recipe scroll drop chances and world-drop marking (`ns.ScrollDrops`, `ns.WorldDrops`, loot tables); AtlasLoot's
  rate replaces the bundled one where it has one.
- Which gathering skill yields a reagent (`ns.GatheredBy`) and a node's required skill (`ns.NodeSkills`, the
  `gameobject_template` lock with the client's `Lock` DB2).
- Reagents a creature drops often enough to loot (`ns.LootedFrom`, `creature_loot_template`).
- The quest that teaches a profession rank (`ns.RankQuests`, `quest_template` RewSpell); title and giver are QuestieDB's.
- Limited vendor stock (`ns.LimitedStock` in `Data/Sources.lua`, `npc_vendor.maxcount`). A scroll's vendor price is
  not bundled: it is the one seen at a merchant. `Data/Recipes.lua`, `Thresholds.lua` and `Vendor.lua` come from the
  client's own DB2 tables through wago.tools.
